# Changelog

## Unreleased

- `publishPendingComments` now publishes drafts on Bitbucket Cloud. It posts a copy of each of the authenticated user's drafts with `pending: false`, then deletes the draft. A draft root goes first, so its draft replies point at the new id. An outdated inline draft is posted at file level. It takes an optional `comment_ids` filter and returns one row per draft: `draft_id`, `new_id`, `status` (`published`, `post_failed`, `delete_failed`, `skipped`) and the tasks on the draft. It deletes the drafts after every copy is posted, replies before their roots. A failed post keeps the draft; a failed delete after a good post is reported as a duplicate risk and is never retried. It fails when `GET /user` does not identify the caller, and when `comment_ids` is not a non-empty list of ids.
- `getPullRequests` drops the repeated copies Bitbucket returns when `q` filters on a list field such as `reviewers.uuid`.
- **Security:** the log no longer records credentials. A logged axios error carried the request config, so `BITBUCKET_PASSWORD` (from the `auth` option) reached the log file in clear text. Every log entry now passes through a redactor that blanks secret keys and Basic/Bearer credentials, and the log file is created (or tightened) to mode `600`. Rotate any app password or token used with an earlier version, and delete its old log file.
- Basic credentials (`BITBUCKET_USERNAME` + `BITBUCKET_PASSWORD`) now travel as an `Authorization` header. Axios dropped its `auth` option on redirects, so `getPullRequestDiffStat`, which Bitbucket answers with a same-host 302, failed with 404.
- `getPullRequests` takes `q` (BBQL), `sort`, `fields` and `next`, and returns `{ values, page, pagelen, next }`. A default projection keeps each pull request small; a MERGED list returned megabytes before. Bitbucket ignores `state` once `q` is set, so the tool folds `state` into `q`.
- Every tool error now carries the HTTP status, the request and Bitbucket's error message, detail and fields.
- `getPullRequestComments` now returns `{ values, page, pagelen, next }`. It previously returned only the first 10 comments and dropped the `next` link, so callers had no way to tell that a review thread had been truncated. One page stays the default; `all: true` fetches every page.
- `getPullRequestComments` now omits deleted comments and every reply below a deleted thread root. Bitbucket keeps deleted comments in the collection with their content blanked out, so withdrawn feedback was reaching callers as if it were still live.
- `publishPendingComments` now reports how many comments it actually published and raises an error when none could be published. Bitbucket Cloud rejects `pending` on `PUT /comments/{id}` with `{"fields": {"pending": "extra keys not allowed"}}`, so every publish failed while the tool still reported `Published N pending comments`.
- Documented in the `addPendingPullRequestComment` and `publishPendingComments` tool descriptions that Bitbucket Cloud exposes no REST endpoint for publishing a draft comment.
- Added Jest tests for the deleted-thread filter, covering deleted roots, deleted replies, missing parents, cyclic ancestry, and mixed string/number comment ids.
- Added a shared Bitbucket Cloud pagination helper and applied it across all list-style MCP tools so `pagelen`, `page`, and `all` arguments respect Bitbucket limits and `next` links (#37).
- Updated tool schemas, README documentation, and logging to describe the new pagination controls and to highlight the 1,000-item safety cap for `all=true`.
- Added Jest tests covering the pagination helper, including explicit `pagelen` requests, maximum page sizing, and automatic traversal of `next` links.
